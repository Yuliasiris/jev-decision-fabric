# Caller-owned CSV use

The runnable [CSV consumer](../consumers/csv-audit/README.md) imports only public `jev-decision-fabric`, `/contract` and `/controller` exports plus Node builtins. It is separate from the packaged numbers/policies reference and from the fixed deployed plugin tools. A normal caller supplies ordinary audit/total prose and their explicit CSV file, numeric column, unit and private state directory.

Its fixed registry recipe is `csv-read` → `csv-audit` → `csv-report`. `createWork` supplies the original run; `restoreWork` supplies graceful reentry to the same SDK snapshot. The consumer hosts filesystem checks, one exclusive local writer and durable archive/readback callbacks; it does not implement another controller, grant store or planner-state engine. Planner and final receipts are honestly `scripted`. Actual file I/O and exact decimal calculation are the demonstrated effects. Jev/native calls are zero and tokens/cost remain unknown.

Start with `--pause-after-read` to inspect the accepted read before the audit. Resume in another process before the original three-minute deadline. The original run ID, source SHA/revision, registered read attempt, max-eight parent operation budget and zero-decision allocation remain unchanged. A normal paused execution uses three parent operations; completing after resume uses seven. Status shows the original answer and provenance without replaying work. The default human text and stdout JSON derive from one saved result record, including current state, next operation and whether the delivery is a saved record.

Malformed CSV produces an invalid observation, a stopped/failed result and no answer or partial total. Changed input blocks resume while preserving the original snapshot; restoring the exact bytes is the same-run repair. Corrupt snapshots/results/archive records are refused, and an intact original private archive is needed for recovery. A conflicting or stale writer lock is never broken automatically. The consumer does not refresh expired deadlines or retry unknown effects. Status labels an expired unfinished run while retaining its original historical result.

Every caller CSV read uses one opened descriptor, a regular-file check and a fixed 32 KiB + 1-byte buffer. Oversized inputs and detected changes within the read are refused and the descriptor closes. Before/after timestamps constrain only that individual read; restoring exact original bytes for resume is still permitted, including replacement through an ordinary regular-file symlink. POSIX uses nonblocking open; Windows uses its native read-only open with the same descriptor checks. No other platform silently falls back when the flag is unavailable. Native execution is currently exercised on Linux; the Windows branch has a focused substitute check only. Access to an unresponsive filesystem is not qualified as interruptible. Human stderr escapes C0/C1 controls and Unicode U+2028/U+2029 separators in success, saved-history and error fields while retaining deliberate answer LF separators; structured records and raw source data remain original.

See the consumer README for the public tarball installation, own-file commands, supported numeric CSV syntax and privacy boundaries. This route is a local scripted use, not a general natural-language planner, live Jev/native comparison or an authenticated remote adoption. The source and example CSV are project-authored under the repository MIT license; dependencies/services retain their own terms.
